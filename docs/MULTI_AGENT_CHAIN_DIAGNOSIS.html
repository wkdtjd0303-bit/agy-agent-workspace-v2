🔍 다중 협업 모드(!mode 2, 2+) Coder ➔ QA ➔ Auditor 연계 누락 원인 정밀 진단

📋 핵심 요약

다중 협업 모드 세팅 시 Coder만 실행되고 QA나 Auditor로 연계되지 않는 현상은 단일 버그가 아닌 6가지 서로 다른 시스템 분기 및 차단 게이트에 의해 발생합니다. 특히 Coder 응답 내 이모지 오판정(Early Exit), 프롬프트의 ResearchRunner 오분류, Zero-Production-Diff 기계적 차단이 주원인입니다.

🚨 6대 핵심 원인 상세

원인 1 · 치명적 조기 종료
Coder 응답 이모지(🚨, 🛑, ⚠️)에 의한 is_system_error() 오판정
  • 발생 위치: trio_agent_runner.py Line 232, Line 925
  • 메커니즘: Coder 모델이 답변 작성 시 강조를 위해 🚨 **[긴급 패치 내역]** 또는 ⚠️ **[오류 원인]** 등으로 시작하면, 시스템이 이를 실제 에이전트 실패(치명적 에러)로 간주하고 QA/Auditor를 전혀 호출하지 않은 채 즉시 파이프라인을 종료합니다.
원인 2 · 파이프라인 탈취
자연어 분석/원인 조사 프롬프트의 ResearchRunner 탈취 및 다중 QA 누락
  • 발생 위치: mode_classifier.py Line 367, bot.py Line 4499
  • 메커니즘: 사용자가 !mode 2+ 상태에서 "원인을 찾아봐줄래?", "비교해줘", "분석해줘" 등을 입력하면 task_type="research"로 분류되어 ResearchRunner로 분기됩니다.
  • 결함: ResearchRunner는 확장 QA(qa2~qa7) 파라미터가 아예 없어 다중 QA가 단 한 대도 실행되지 않으며, Coder에게 시세 조사용 리서치 프롬프트가 주입됩니다.
원인 3 · 기계적 게이트 차단
Zero-Production-Diff 게이트에 의한 QA 이관 거부
  • 발생 위치: trio_agent_runner.py Line 1070, evidence_validator.py Line 557
  • 메커니즘: Coder가 설정 파일(.env, package.json, build.gradle), 문서(README.md), 테스트(test_*.py)만 수정한 경우, 프로덕션 소스코드 git diff가 0줄로 판정되어 시스템이 QA/Auditor 이관을 원천 거부하고 Coder 재작업을 지시하거나 최대 라운드 도달 시 종료합니다.
원인 4 · 빌드 점검 차단
Pre-Flight 컴파일 사전 점검 실패 루프
  • 발생 위치: trio_agent_runner.py Line 1116
  • 메커니즘: 안드로이드/Gradle 프로젝트 등에서 Coder의 수정본이 compileDebugSources 에러를 유발하면 QA 단계로 넘기지 않고 Coder 자가수정을 강제합니다.
원인 5 · 인프라/API 장애
OpenRouter API 쿼터 고갈 및 180초 타임아웃
  • 발생 위치: trio_agent_runner.py Line 1613-1639
  • 메커니즘: 확장 QA 순차 호출 중 OpenRouter 쿼터 소진, 크레딧 부족, 또는 180초 응답 지연 발생 시 예외가 발생하여 전체 루프가 중단됩니다.
원인 6 · 디스코드 권한
QA/Auditor 봇의 채널 메시지 전송 권한 누락
  • 발생 위치: trio_agent_runner.py Line 1245
  • 메커니즘: 특정 채널에서 QA 봇 클라이언트가 Send Messages 권한이 없을 경우, 비방어적 send() 호출이 discord.Forbidden (403)을 발생시켜 상위 에러 핸들러로 튕깁니다.

💡 권장 해결 방안 (패치 방향)

  • is_system_error 판정 정교화: 단순 🚨 이모지 시작 체크를 폐지하고 시스템 고유 에러 태그(🚨 **[Zero-Production-Diff 등)로 한정하여 Coder 정상 답변 조기 종료 차단
  • mode_classifier 오분류 방어: 코드/시스템 디버깅용 "원인 분석/조사" 질의를 research가 아닌 coding 또는 diagnostic으로 정확히 분류
  • ResearchRunner 다중 QA 지원: 리서치 파이프라인에서도 !mode 2+ 확장 QA가 누락되지 않도록 파라미터 연계
  • Zero-Production-Diff 예외 확대: 설정/인프라/문서/테스트 작업 요청 시 유연하게 QA/Auditor 검증을 허용
