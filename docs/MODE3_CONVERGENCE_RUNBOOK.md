# `!mode 3` 수렴 계약 · 시각 증거 공유 — 운영 런북

> 대상: `agy_agent` 무인 자율 순환(`!mode 3` / `!mode 3+`)
> 최종 갱신: v12 수렴 개선 3차 커밋 기준

---

## 1. 왜 이 작업이 있었나

무인 자율 루프가 **7라운드를 끝까지 소진하면서도 승인되지 못하는** 상황이 반복됐다.
원인은 "QA가 너무 엄격해서"가 아니었다. 실제 결함은 다음 3가지였다.

| # | 결함 | 결과 |
|---|---|---|
| 1 | **껍데기/도달불가 구현** — 동작 안 하는 애니메이션, 도달 불가한 에러 화면, 데이터 손실 버그 | 사용자에게 잘못된 화면 제공 |
| 2 | **증거 위장** — 실행 안 된 계측을 "OK (10 tests)", ANR 다이얼로그를 "나이트 화면"으로 제출 | 감사 신뢰 붕괴 |
| 3 | **범위 자기증식** — "앱을 예쁘게"가 아니라 "완벽한 증거 시스템"으로 번져나감 | 사용자 목표에서 이탈 |

따라서 해법은 "QA를 느슨하게"가 아니라 **판정 기준을 기계화하고 증거 재사용을 구조적으로 차단**하는 것이었다.

---

## 2. 무엇이 동작하는가

### 2-1. 수렴 계약 (차단/비차단 분리)

- QA는 반려 시 판정과 무관하게 둘째 줄에 `[BLOCKING_DEFECTS: N]`을 표기한다.
- `N == 0` → 남은 건 비차단(스타일/문서/리팩토링)뿐 → **승인으로 수렴 + 백로그 이관**
- `N`이 **2회 연속 감소하지 않으면** → 라운드 상한 전에 **조기 에스컬레이션** (상한까지 태우지 않음)
- **정직성 위반은 비차단 면제 대상이 아니다.** 실행 안 한 테스트 통과 기재, 상태를 표현하지 않는 캡처 제출 → 즉시 반려.
- 마커가 없으면 `estimate_blocking_defect_count()` 휴리스틱이 보정한다 → **정책이 조용히 죽지 않는다.**

관련 코드: `convergence_policy.py`, `trio_agent_runner.py`, 헌법 9조(3곳)

### 2-2. 시각 증거 디스코드 공유

- `!mode 3/3+` 매 라운드 실제 렌더링 화면을 **디스코드에 이미지로 전송** (최대 4장, 최신순)
- 사용자 참고 이미지(sha256/dHash)는 **절대 전송 안 함** (표절 오인 방지)
- 빈/검은 화면·저해상도 제외, 8MB 초과 제외, 라운드 간 해시 중복 전송 방지

관련 코드: `discord_screenshot_gallery.py`

### 2-3. 라운드 경계 (스크린샷 재사용 차단)

`REJECTED → 재작업 → 빌드/재설치 → 재실행 → 캡처 → 공유` 사이클에서
**이전 라운드 캡처가 이번 라운드 증거로 재사용되는 것을 구조적으로 차단**한다.

- 라운드마다 `_round_start_ts`를 찍고 시각 소비 3경로에 바인딩
  - VCL `run_round(session_start_time=…)`
  - Gemini Vision 사전 검사(`min_mtime=…`)
  - 디스코드 갤러리(`min_mtime=…`)
- 이번 라운드 신규 캡처 0장 + 과거 캡처 존재 → **공유 생략 + 신선도 경고 알림**

## 3. 검증 방법 (3중)

### 3-1. 회귀 스위트
```bash
cd agy_agent && .venv/bin/python -m pytest tests/ -q
```
기대: `0 failed`. (신규 테스트는 수렴 정책·갤러리·신선도 3영역)

### 3-2. 실기기 시나리오 (에뮬레이터 필요)
```bash
# 1) 에뮬레이터를 "콜드부트"로 띄운다 (스냅샷 잔재로 부팅이 막히는 것을 방지)
~/Android/Sdk/emulator/emulator -avd TestAVD \
    -no-window -no-audio -no-boot-anim -no-snapshot \
    -gpu swiftshader_indirect -no-metrics &

# 2) 재사용 시나리오 검증
.venv/bin/python scripts/verify_screenshot_roundcycle.py
```
기대 출력:
```
[PASS] Round 1 — 신규 캡처 공유
[PASS] Round 2 — 캡처 없을 때 이전 스크린샷 재사용 금지(공유 0 + 경고)
[PASS] Round 3 — 재설치 후 새 캡처만 공유(round1 재사용 없음)
```

> 이 머신에서 KVM 가속이 확인되어 부팅은 약 25초다.
> `-no-snapshot`을 생략하면 `TestAVD`의 잔여 스냅샷 때문에
> "A snapshot operation is pending"으로 부팅이 막힐 수 있다.

### 3-3. 수렴 계측 리포트 (마지막 판단 근거)

`!mode 3` 미션이 어떤 경로로 끝나든(승인/최대 라운드/에스컬레이션/예외) 다음 파일이 생성된다.

```
<워크스페이스>/reports/convergence_telemetry.json
```

판독법:

| 필드 | 의미 | 이상 신호 |
|---|---|---|
| `marker_emission_rate` | QA가 `[BLOCKING_DEFECTS]`를 지킨 비율 | **0에 가까우면 프롬프트 계약 미준수** |
| `heuristic_used` | 휴리스틱 폴백이 대신 판정한 횟수 | 높으면 마커 계약이 사실상 무력 |
| `unresolved` | 판정 실패 횟수 | `observations`와 같으면 **정책 비활성** |
| `contract_active` | 계약이 실제로 작동 중인지 | `false`면 개선이 동작하지 않은 것 |
| `force_accepts` / `escalations` | 수렴 승인 / 조기 중단 발생 횟수 | |

> **원칙: 리포트 없이 "개선 완료"라고 말하지 않는다.**
> `contract_active: true`가 확인되기 전까지는 효과 미확증이다.

## 4. 남은 유일한 미증명 항목

**실제 Discord 채널 + 실제 안드로이드 앱에서의 `!mode 3` 완주 검증.**

지금까지의 검증은 (1) 단위 테스트, (2) 실제 에뮬레이터 캡처를 사용한 **시뮬레이션**,
(3) 계측 코드 자체의 테스트다. Discord 전송은 mock이었고, 라운드 흐름은 수동 재현이었다.

### 드라이런 절차 (권장)

1. 테스트용 Discord 채널을 만들고 그 채널에서 `!mode 3`을 활성화한다.
2. Android 앱이 있는 워크스페이스를 대상으로 짧은 요청을 던진다
   (예: `!mode 3 메인 화면 버튼 간격과 색상 정리 좀 해줘`).
3. 종료 후 아래를 확인한다.

```bash
cat <워크스페이스>/reports/convergence_telemetry.json
```

- `contract_active: true`
- `marker_emission_rate` 값 확인 (0이면 QA 프롬프트 계약 조정 필요)
- 디스코드에 `🎨 [라운드 N] 시각 증거 스크린샷` 이미지가 올라왔는지
- 반복 반려 시 라운드가 7까지 가거나 멈추지 않고 **조기 수렴/에스컬레이션**으로 끝났는지

## 5. 알려진 한계

- **`min_mtime` 1초 허용 오차**: 파일시스템 타임스탬프 정밀도 보존용. 라운드는 분 단위라
  실전 영향은 없지만, 캡처 직후 1초 안에 다음 라운드가 시작되는 극단적 경우엔 직전 캡처가 후보에 남을 수 있다.
- **휴리스틱 폴백은 완전하지 않다**: 키워드 분류이므로 표현이 낯선 결함은 놓칠 수 있다.
  다만 "모호하면 차단으로 lean"하도록 설계해 오승인 방향으로만 기울어진다.
- **Visual Craft Loop은 측정 기반**(`visual_craft_loop.py`). 에뮬레이터/기기가 불안정하면
  캡처 자체가 0장이 되어 시각 게이트가 자동으로 OFF된다. 이때는 `BLOCKED`로 정직하게 기록되어야 하며,
  `PASS` 위장은 헌법 위반이다.
- **성능**: 라운드당 이미지 추가로 Discord 대역폭/레이트리및 영향은 소규모 검증에 그췄다.
