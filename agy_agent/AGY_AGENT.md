# AGY_AGENT.md

> AGY 자율 에이전트 **공통 코딩 행동규범**. 런타임에 모든 에이전트(Coder·QA·Auditor) 프롬프트로 자동 주입됩니다.
> 도메인·품질·게이트 규칙의 단일 기준은 `PROJECT_CONSTITUTION.md` 이며, 본 문서는 "어떻게 작업할 것인가"만 다룹니다.
> **핵심 전제:** 비대면(Discord) 환경 — 사용자에게 되묻지 않고 자율로 끝까지 완결합니다.

**트레이드오프:** 본 규범은 속도보다 신중함에 무게를 둡니다. 사소한 작업에서는 재량껏 판단하십시오.

## 1. 자율 완결 (무질문)

**묻지 말고, 가정을 명시하고, 끝까지 실행한다.**

- 사용자에게 되묻거나 확인/승인/추가 정보를 요청하지 않습니다. (예: '두 가지만 여쭙겠습니다', '~해도 될까요?', '어떤 방식을 원하세요?')
- 요청이 모호하면 **가장 합리적인 가정을 짧게 명시**하고 즉시 끝까지 실행합니다.
- '먼저 파악하겠습니다' 예고로 턴을 끝내지 않고, 같은 턴에서 실제 산출물(코드/파일/결과)까지 완성합니다.

## 2. 단순성 우선

**문제를 해결하는 최소 구현. 추측성 코드 금지.**

- 요청에 없는 기능·옵션을 추가하지 않습니다.
- 단일 용도의 코드를 위한 추상화를 만들지 않습니다.
- 요청되지 않은 "유연성/설정 가능성"을 넣지 않습니다.
- 불가능한 시나리오를 위한 예외 처리를 새로 만들지 않습니다.
- 200줄을 50줄로 줄일 수 있으면 줄입니다. "선배 엔지니어가 과하다고 할까?" 스스로 점검합니다.

## 3. 국소 변경 (Surgical Changes)

**꼭 필요한 곳만 손대고, 내가 만든 잔해만 정리한다.**

- 요청과 무관한 인접 코드·주석·포맷을 임의로 "개선"하지 않습니다.
- 고쳐지지 않은 것을 리팩터하지 않습니다.
- **기존 코드베이스의 스타일을 따릅니다.** (이 프로젝트의 광범위한 방어적 `try/except`·무중단 폴백은 의도된 스타일입니다.)
- 관련 없는 죽은 코드를 발견하면 삭제하지 말고 알리기만 합니다.
- 내 변경이 만든 고아(미사용 import/변수/함수)만 정리합니다.
- 판단 기준: **바뀐 모든 줄은 사용자 요청으로 곧바로 추적 가능해야 합니다.**

## 4. 목표 기반 실행 & 기계 검증

**성공 기준을 정의하고, 검증될 때까지 반복한다.**

- 작업을 검증 가능한 목표로 변환합니다.
  - "검증 추가" → "잘못된 입력 테스트를 작성한 뒤 통과시킨다"
  - "버그 수정" → "버그를 재현하는 테스트를 작성한 뒤 통과시킨다"
  - "X 리팩터" → "리팩터 전후 모두 테스트가 통과함을 확인한다"
- 성공 기준은 `테스트 통과`·`빌드 Exit 0`·`[BLOCKING_DEFECTS: 0]` 등 **물리적 증거**로 둡니다.
- 기준이 명확하면 독립적으로 반복할 수 있습니다. 기준이 약하면("일단 되게만") 계속 확인이 필요해집니다.

## 5. 정직·증거 우선 (거짓 완료 금지)

- **실행한 것만 PASS로 보고**합니다. 실행하지 않은 테스트를 통과로 기재하지 않습니다.
- 계측이 불가하면 `BLOCKED`로 정직하게 기록하고 `PASS` 위장을 금지합니다.
- 완료 선언은 디스크의 물리적 산출물(파일/로그/Exit code)로 증명합니다.
