# 📦 Product Value Planning — Commander 제품 가치 기획 & 하드닝 단독 마일스톤 차단

> **"품질 하드닝은 기획이 아니다. 기획자는 '사용자가 화면·동작에서 아직 체감하지 못한 신규 기능'을
> 다음 마일스톤으로 발주한다."**

---

## 1. 문제 정의 (왜 필요했는가)

Commander의 결정론적 폴백은 도메인 사다리(코어 → 시각 → 오디오 → 게임필 → 레벨 → E2E)가
끝나면, 아직 사용자에게 줄 기능이 남아 있어도 곧바로 다음 과제로 수렴했습니다.

- ❌ `상용 배포 품질 하드닝 및 E2E 회귀 검증`
- ❌ `경계 조건 및 대용량 데이터 입력 시 크래시 방어`
- ❌ `응답 속도 최적화 및 불필요한 연산 제거`
- ❌ `전체 E2E 시나리오 테스트 100% 무결점 통과`

겉보기에는 성실해 보이지만, **사용자가 화면에서 새로 체감하는 가치는 0**입니다. 이는 QA/엔지니어의
역할이지 기획자(Commander)의 역할이 아닙니다. 품질 담금질은 신규 가치 기능에 딸린 부산물이어야
합니다.

기존 `planner_visual_gap_analyzer.py`(스크린샷 실측 결손)는 훌륭하지만, **'이미 렌더링된 화면'이
존재할 때만** 동작합니다. 초기/헤드리스/CLI/백엔드 프로젝트, 혹은 아직 스크린샷이 없는 라운드에서는
물리 증거가 없어(`None`) 곧바로 위 하드닝 폴백으로 떨어졌습니다.

## 2. 해결 (What's new)

`product_value_planner.py` 가 "화면 증거가 없을 때의 기획 공백"을 닫습니다.

```
[디스크 물리 증거]  (구현 컴포넌트 / 소스 파일 / 완료·진행 마일스톤)
        │
        ├─ 도메인별 사용자 가치 카탈로그와 대조 (이미 구현된 기능은 건너뜀)
        │
        ▼
[가장 가치 높은 미구현 사용자 기능 1건]  (예: 일시정지·옵션 메뉴 / 원클릭 내보내기·공유)
        │
        ├─ 하드닝 전용(hardening-only) 기획이면 → 강제 교체
        │
        ▼
[차기 원자적 마일스톤]  (source = product_value)
```

### 도메인별 사용자 가치 카탈로그 (가치 순)

| 도메인 | 대표 가치 기능 |
|---|---|
| `saas_web` | 내보내기·공유, 검색·필터, 설정, 다크 모드/테마, 알림·리마인더, 이력·협업, 온보딩·도움말, 접근성·단축키, 다국어, 백업·복원 |
| `mobile_app` | 설정, 즐겨찾기·최근 항목, 검색·필터, 공유·내보내기, 다크 모드, 알림·리마인더, 오프라인, 접근성, 다국어, 백업 |
| `game` | 일시정지·옵션, 업적·도전과제, 리더보드, 스킨 상점, 게임 모드 변주, 사운드·진동 설정, 튜토리얼, 다국어 |
| `cli_agent` / `daemon` | 대화형 REPL, 셸 자동완성·매뉴얼, 출력 포맷(json/yaml/table), 설정 프로필, 플러그인, 배치·스케줄, 다국어, 테마 |
| `backend_api` | 페이지네이션·필터·정렬, 검색 API, OpenAPI 문서, 웹훅, 파일 업로드, 인증·권한(RBAC), 벌크 API, 감사 로그, 버저닝 |
| `generic` | 내보내기·공유, 검색·필터, 설정·개인화, 알림, 온보딩, 접근성, 다국어, 백업·복원 |

### 하드닝 전용 판정 (`is_hardening_only_plan`)

- 제목 자체가 `하드닝 / 품질 안정화 / 회귀 검증 / 100% 통과 / 경계 조건 / 대용량 데이터 /
  크래시 방어 / 응답 속도 / 불필요한 연산 / production hardening …` 표지면 즉시 `True`.
- 그 외에는 **모든 태스크가** 방어·검증 성격일 때만 `True`
  (가치 기능 1개 + 방어 1개 혼합은 정상 기획이므로 차단하지 않음).

## 3. COMMANDER 통합 지점

| 경로 | 파일/함수 | 동작 |
|---|---|---|
| 차기 마일스톤 (동기/폴백) | `Commander._build_heuristic_adaptive_plan` (종단) | 하드닝 단독 폴백을 `_prefer_value_over_hardening` 으로 가치 기능 플랜으로 교체 |
| 차기 마일스톤 (비동기/AI) | `Commander.plan_adaptive_next_milestone_async` | AI/휴리스틱 기획이 하드닝으로 수렴하면 가치 기능으로 교체 |
| 차기 마일스톤 (동기) | `Commander.plan_adaptive_next_milestone` | 동일 가드 적용 |
| AI 5W1H 기획 프롬프트 | `plan_milestone_5w1h_async` Mandate 8 | "VISUAL GAP FIRST & PRODUCT VALUE OVER HARDENING" — 화면 결손이 없어도 사용자 기능을 발주하도록 강제 |
| 로드맵 자동 확장 | `RoadmapManager.auto_expand_roadmap` | 하드닝 템플릿보다 제품 가치 기능을 먼저 후보로 승격 (최대 1건) |
| 일반론 차단 가드 | `Commander._prefer_visual_gap_over_generic` / `PlannerVisualGapAnalyzer.is_generic_validation_plan` | 하드닝/일반론 판정을 `ProductValuePlanner` 로 위임 |

### 절대 덮어쓰지 않는 플랜 (불변성)

`source ∈ {feedback, depth, signal, visual_gap, product_value}` 플랜은 가치 교체 대상에서 제외됩니다.
→ 사용자 피드백, 디스크 코드 신호(테스트 실패/크래시/스텁), 심도 심화, 스크린샷 결손은 그대로 우선합니다.

## 4. 표시 & 설정

- `Milestone5W1HPlan.product_value_analysis` 필드가 Discord 메시지/임베드에
  **`📦 제품 가치 기획 (아직 없는 사용자 기능)`** 블록으로 표시됩니다. (source 배지: 📦 `product_value`)
- Coder 훈령(`build_directive_for_coder`)에도 **`📦 제품 가치 기획`** 섹션이 동봉되어,
  "품질 하드닝이 아니라 사용자가 새로 체감하는 기능을 구현"하도록 지시합니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `COMMANDER_PRODUCT_VALUE_ENABLED` | `1` | Commander 기획 단계 제품 가치 기획 ON/OFF |

## 5. 안전장치 (Zero-Regression)

1. **이미 구현된 기능 재기획 차단**: 카탈로그의 `detect` 토큰(컴포넌트/소스 파일/완료·진행
   마일스톤)이 디스크에 있으면 해당 기능은 결손 후보에서 제외합니다.
2. **도메인 무관 환각 금지**: 카탈로그는 도메인별로 격리되어, 웹 프로젝트에 게임 AI나 신디사이저
   같은 무관 기능이 발주되지 않습니다.
3. **가치 기능 소진 시에만 하드닝 허용**: 카탈로그가 모두 구현되어 후보가 0건이면 그때만 기존
   하드닝 폴백을 그대로 사용합니다 (fail-safe).
4. **읽기 전용**: 이 모듈은 제품 소스코드를 수정하지 않습니다.
5. **테스트 격리**: 결정론적 순수 함수로 구성되어 네트워크/LLM 없이 검증됩니다.
   (`tests/test_product_value_planner.py`)

## 6. 예시 (사용자 관점)

> "사과 피하기 게임을 만들고 있어."

코어 루프(캔버스 → 플레이어 → 사과 낙하 → 충돌/게임오버 → 스코어 HUD)가 디스크에 완성되면,
기존에는 `상용 배포 품질 하드닝 및 E2E 회귀 검증` 이 발주되었습니다.
이제는 화면에 아직 없는 **`일시정지·재개 및 옵션 메뉴`** 가 다음 마일스톤으로 발주되고,
그 다음은 업적·도전과제 → 리더보드 → … 로 사용자 가치가 이어집니다.
